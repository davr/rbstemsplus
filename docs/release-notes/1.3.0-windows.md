RB Stems Plus 1.3 on Windows: prepare a playlist's stems before a set.

These notes cover what is different on Windows. The Mac notes are in `1.3.0.md`.

## What's new on Windows

- **Prepare playlists.** The new **Prepare** tab lists rekordbox's playlists. Choose one and RB
  Stems Plus says how many tracks are ready, how many it will prepare, how much space that takes
  and about how long. **Prepare** makes their stems in advance, in the background, so every
  track loads with its stems at once in rekordbox. **Pause** and **Stop** are there; what is done
  stays done. Needs Stems Cache and Demucs v4.
- **Fast on an NVIDIA GPU.** With the optional CUDA runtime, preparing runs at about 25 times
  real time (RTX 4060 laptop): a 15-track playlist takes about 7 minutes. Without it the CPU is
  used, at about 3 times real time.
- **Kept until a date you choose** (10 days by default): Stems Cache doesn't remove prepared
  stems meanwhile. Up to 5 playlists, using at most 75% of Stems Cache's size limit.
- **Checked when rekordbox opens.** The **Status** tab lists your prepared playlists and whether
  each one is still ready. When you open rekordbox, RB Stems Plus checks them too and shows a
  Windows notification if a track isn't fully prepared any more, or was added since.
- **A new window:** three tabs, **Status**, **Prepare** and **Manage**. Each feature has its own
  **Reinstall** button on the Manage tab.
- **Reinstalling after a rekordbox update:** RB Stems Plus now asks once rekordbox's updater has
  finished and its window is closed.
- **Better logs.** `app.log` records each prepared track, how a run ended, and any error with its
  details.

## Tracks it prepares

MP3, AAC (M4A), ALAC, FLAC, AIFF and WAV, at 44.1 kHz or another sample rate. A prepared track is
found by rekordbox only if RB Stems Plus decodes it exactly as rekordbox does. This was measured on
rekordbox 7.2.14, and checked by loading prepared tracks in rekordbox: MP3, FLAC and AAC at 44.1
and 48 kHz.

## Known gaps

- For some AAC (M4A) files, rekordbox separates the last part of the track (about 11 s) itself
  when you load it. The rest of the track is prepared.
- Only Demucs v4 can be prepared, not rekordbox's own model.
- A track that isn't at 44.1 kHz needs a processor with FMA (Intel and AMD since about 2015).
- A track that can't be prepared shows as "to prepare" on the Status tab, and as skipped, with
  the reason, on the Prepare tab.

## Updating

After updating RB Stems Plus, reinstall Stems Cache from the **Manage** tab (Windows asks for
permission): preparing playlists needs the new Stems Cache.

rekordbox must be set to *Prioritize sound quality* for STEMS (Preferences › Extensions › STEMS):
prepared stems aren't used with *Prioritize speed*.
